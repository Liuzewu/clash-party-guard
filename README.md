# Clash Party Guard

[中文](README.md) · [English](README.en.md)

为 Clash Party 和 Mihomo 的策略组添加故障检测与备用节点切换。短暂波动时保留当前选择；持续失败后，先检查备用节点，再决定是否切换。

项目使用 Python 标准库，通过 Mihomo 控制接口运行。它可以独立使用，也可以作为调整检测与切换策略的起点。

## 先运行演示

需要 Python 3.9 或更高版本，无需安装第三方依赖：

```sh
python3 examples/demo.py
```

演示使用虚构节点和模拟检测结果，展示从故障确认到建议切换的过程，不连接控制器，也不访问互联网。
最后一行的 `would_switch` 表示符合切换条件；演示不会实际修改选择。

## 功能

- 检查当前节点访问指定业务的结果，短暂失败不立即切换。
- 连续失败达到次数和持续时间后，再检查备用节点；切换前重新确认候选可用。
- 检测到用户手动选择后，保留用户的选择。
- 支持配置策略组、业务检测地址、预期状态、候选排除规则和检测间隔。
- 支持预览模式：执行检测并输出建议，但不更改当前节点。
- 后台记录节点检测结果，保持期到期后比较成功率与延迟；候选持续更好并通过复核时，可以升级主节点。
- 故障切换后，原主节点持续恢复并通过复核时，可以自动回切。
- 可读取自行准备的品质数据，或开启后台 IP 品质检测；默认不连接第三方评分服务。
- 可选多设备协调，在家中多台设备之间安排节点切换。
- 可配置手动跟随父策略组；退出跟随后重新进入观察期。

## 连接自己的 Clash Party

1. 确认 Clash Party 的 Mihomo 本机 HTTP 控制接口已启用，准备好控制器地址、策略组名称和两个不同域名的 HTTPS 检测地址。目标组应为 `Selector`，当前选择应是具体节点。
2. 复制 `examples/config.json` 为 `config.json`，将示例地址替换为自己的业务检测地址和预期状态。`health_url` 必须与节点健康检查使用的 URL 完全一致，并有最近五分钟的测速记录。需要认证时，将密钥放在环境变量中，并在 `secret_env` 字段写入该变量名。
3. 先运行预览模式：

   ```sh
   python3 -m clash_guard --config config.json --dry-run
   ```

   预览模式会访问控制器、对配置的业务地址发起检测并记录本地历史，但不会切换节点。只想查看当前策略组、不做检测或保存历史时，可以运行：

   ```sh
   python3 -m clash_guard --config config.json --read-only
   ```

4. 确认配置和输出符合预期后，开启自动切换：

   ```sh
   python3 -m clash_guard --config config.json --enable-switch
   ```

程序运行期间持续检查，按 `Ctrl+C` 停止。状态默认保存在 `~/.local/state/clash-party-guard/` 下，按策略组区分；预览与自动切换使用各自的目录，预览期间积累的历史和自动评分不会转入正式运行。可用 `--state-dir` 指定目录：同一状态目录一次只能运行一个守护进程；自定义目录时，也请为预览和正式运行分别指定。保持期、采样门槛、恢复时间等参数可在配置中调整。

如需参考自行准备的品质数据，可在配置中添加 `quality_file`，指向本地 JSON 文件，格式见 [品质数据示例](examples/quality.example.json)。`score` 为 0–100 分，`observed_at` 为实际测量时间；示例时间需要替换。数据默认有效 24 小时：排序时，同成功率的候选须全部具备有效评分才比较评分；健康升级时，双方评分均有效才要求候选不低于当前节点。

也可配置[自动 IP 品质检测](docs/ip-quality.md)，由本机后台采样并查询第三方评分；或配置[多设备协调](docs/coordination.md)，让在家的设备参与切换。两项功能均需单独配置，默认关闭。若同时配置 `quality_file` 和自动检测，启用自动检测后只使用自动评分，不回退到手动文件。

仓库也提供 [Party 覆写示例](examples/party-override.js)，可将配置中 `proxies` 列出的节点加入指定策略组。使用前需修改组名和筛选规则；使用 provider 的配置需要另行适配。

## 手动跟随父组

如需在 Clash Party 中手动选择其他策略组，先确保该父组是当前策略组的可选项，再在守护配置的顶层列出允许跟随的父组名称，例如：

```json
"follow_parent_groups": ["Parent Selector"]
```

父组必须是 `Selector`。也可修改 [Party 覆写示例](examples/party-override.js)中的 `followParentGroups`，将有效父组加入选项；它不会自动选中父组。手动选中后，守护程序暂停本组探测与自动选节点，取消正在进行的品质采样并暂停调度。父组路径缺失或循环时输出 `follow_parent_unavailable`。退出跟随后恢复采样调度，重新确定主节点，并按 `startup_grace` 进入观察期。多设备协同中的行为见[协同说明](docs/coordination.md)。

python3 -m unittest discover -s tests -v

## 当前范围

使用自动评分或多设备协同时，若配置了动态节点来源（`node_config_path` 或 `identity_command`），守护程序会按节点参数核对本地历史：参数变化或节点下线时归档旧记录并清除原主节点资格；身份暂时未知时暂停健康升级和旧主回切，故障仍可在双重复核后恢复。同时使用多个动态来源时，它们须提供一致的节点配置。

未配置动态节点来源时，检测历史按名称关联，无法识别同名节点参数变化；静态 `node_ids` 或 `identity_file` 也无法自动识别。手动提供的品质数据同样按名称关联。多设备和自动评分的测试在隔离环境运行，尚未完成真实跨设备和外部评分服务的端到端验收；实际业务表现取决于本机网络和所选节点。
